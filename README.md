# パーキングルート

目的地（店・施設）を設定すると、その周辺のおすすめ駐車場をレコメンドし、
決めたルートを **Google マップに引き渡す** ルート案内アプリです。

駐車場をレコメンドするかどうかはトグルで選べます。OFF にすれば目的地まで直行のルートになります。

## 公開（GitHub Pages）

`.github/workflows/deploy.yml` が `main` へのプッシュで自動的にビルドしてデプロイします。
型チェックとテストが通らなければデプロイされません。

初回だけ、GitHub 側で 2 つ設定が必要です。

1. **リポジトリを public にする**
   Settings → 一番下の Danger Zone → *Change repository visibility* → Public
   （private のままだと GitHub Pages は有料プランが必要です）
2. **Pages を有効にする**
   Settings → Pages → *Source* を **GitHub Actions** に変更

公開先は `https://<ユーザー名>.github.io/<リポジトリ名>/` です。
サブパス配下で配信されるため、ビルド時に `BASE_PATH` 環境変数でベースパスを渡しています
（ワークフローがリポジトリ名から自動で組み立てます）。

## 使い方

```bash
npm install
npm run dev      # http://localhost:5173
```

APIキーの設定は不要です。そのまま動きます。

## 画面の流れ

1. **出発地を指定（任意）** — 「現在地」ボタン、または検索。設定しておくと目的地検索が現在地の近い順になる
2. **目的地を検索** — 店名・施設名・住所を入れると自動で候補が出る
3. **駐車場をおすすめする（トグル）**
   - **ON** — 「周辺の駐車場を検索」を押すと候補がスコア順に出る。カードか地図のピンで 1 つ選ぶ
   - **OFF** — 駐車場をはさまず目的地まで直行
4. **ルート確定** — 下部のボタンで Google マップを開く

地点検索は入力が落ち着いてから（450ms）自動で走ります。
一方、**駐車場の検索は明示的にボタンを押したときだけ**実行します。
絞り込みを変えている途中で何度も Overpass を叩かないようにするためです。

## 地点検索

店名で引けないことが多かったため、多段構えにしています。

**ジオコーダはタイポを許容するので「結果が 0 件かどうか」では当たり外れを判定できません。**
無関係な地点をそれらしく返してくるためです。そこで `matchScore`（名前に検索語が
含まれるか）で当たりを判定し、当たりが出るまで次の順に手を広げます。

1. **Photon と Nominatim を同時に引く**
   Photon（komoot）は POI 名の検索とタイポに強く、Nominatim は住所に強い
2. **名前の合う結果が無ければ、語を落として引き直す**
   全角空白を含めて正規化し、長い語から順に試す。「台湾鍋　民生炒飯」→「民生炒飯」。
   OSM には屋号だけが登録されていることが多いため
3. **それでも無ければ Overpass で `name` タグを直接引く**
   語の選択和（`民生炒飯|台湾鍋`）で現在地から 30km 以内。
   チェーン店の各支店など、ジオコーダが上位に出さないものを拾う

集めた結果は **「名前の一致度 → 現在地からの近さ」** で並べ替えます。
距離だけで並べると検索語と無関係な近所の地点が上に来てしまい、
一致度だけだと同名チェーンの遠い支店が上に来るためです。
名前の合う結果が 1 件でもあれば、合わないものは雑音として落とします。

どれか 1 つのサービスが落ちても、残りの結果は返します。

### 現在地の使い方

現在地が分かっていると、両サービスに位置バイアスを渡し（Photon は `lat`/`lon` と
`location_bias_scale=0.1`、Nominatim は `viewbox`）、結果も近い順に並べて距離を表示します。

基準点は **出発地が設定されていればそれ、無ければ端末の現在地**です。
出発地を決めていなくても検索を近所優先にできるよう、両者を切り離しています。

## Google マップへの引き渡し

[Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started) を組み立てて開きます。
アプリが入っていれば Google マップアプリが、なければブラウザ版が開きます。

| ボタン | ルート | travelmode |
| --- | --- | --- |
| 駐車場までナビを開始 | 出発地 → 駐車場（`dir_action=navigate` で即ナビ開始） | driving |
| 駐車場からの徒歩ルート | 駐車場 → 目的地 | walking |
| 駐車場を経由地にして開く | 出発地 → 駐車場（経由）→ 目的地 | driving |
| Google マップでナビを開始（レコメンド OFF 時） | 出発地 → 目的地 | driving |

地点は名前ではなく緯度経度（小数 6 桁）で渡しています。名前で渡すと Google 側の
ジオコーディングで別の同名店舗に解決されることがあるためです。

## レコメンドのしくみ

`src/lib/score.ts` が 4 つの軸を重みづけして 0〜100 のおすすめ度を出します。

| 軸 | 重み | 内容 |
| --- | ---: | --- |
| 近さ | 45 | 目的地からの距離。許容徒歩距離の 2 倍で 0 点 |
| 料金 | 25 | 滞在時間ぶんの概算額で評価（2,000 円で 0 点）。額が読めない場合のみ 無料 > 有料 > 不明 の区分に落とす |
| 収容台数 | 15 | 満車リスクの代理指標。100 台で頭打ち |
| 快適さ | 15 | 屋根あり（立体・地下）、24 時間営業 |

絞り込み（`ParkingFilters`）はスコアリングの前に適用されます。

- 目的地からの距離（200m〜1200m）
- 駐車時間（30分〜12時間）— 料金の見積もりに使う
- 今すぐ停められる（営業時間内のもののみ）
- 無料のみ
- 屋根あり
- 車高 2.1m 以上（`maxheight` タグで判定。制限が未登録のものは残す）

## 料金の見積もり

`src/lib/fee.ts` が OSM の `charge` / `fee:conditions` タグを解析して、滞在時間ぶんの概算額を出します。
日本の駐車場は表記が揺れるため、次のような書式に対応しています。

| 書式 | 例 |
| --- | --- |
| 金額 / 時間 | `300円/30分`、`￥300 ／ 30分`、`300 JPY/30 min` |
| 時間 → 金額 | `1時間400円`、`30分 200円` |
| 最大料金 | `最大1,000円`、`上限 800円`、`24時間最大2000円` |

課金は単位時間ごとの切り上げで計算し（30分単位なら 61 分で 3 単位）、最大料金に達したらそこで頭打ちにします。
**読み取れない文字列は推測せず「料金不明」として扱い**、生の文字列をそのまま表示します。

`maxstay`（最大駐車時間）も読み取り、希望の駐車時間がそれを超える場合はカードに警告を出します。

## 営業時間の判定

`src/lib/openingHours.ts` が `opening_hours` タグを評価し、その時点で営業中かを判定します。
`24/7`、`08:00-20:00`、`Mo-Fr 09:00-18:00; Sa 10:00-16:00; Su off`、`22:00-06:00`（日跨ぎ）、
`09:00-12:00,13:00-18:00`（昼休み）などに対応します。

opening_hours の仕様は非常に大きいため、**確実に読める書式だけを扱い、少しでも怪しいものは「判定不能」として
候補から除外しません**。誤って除外して駐車場を見落とす方が、判定を保留するより害が大きいためです。

一般利用できない駐車場（`access=private` / `no` / `permit`、`parking=private`）は候補から除外します。
同じ駐車場が node と way の両方で登録されている場合は、同名かつ 30m 以内なら 1 件に束ねます。

## データソース

| 用途 | サービス |
| --- | --- |
| 地点検索（POI・タイポ許容・位置バイアス） | [Photon](https://photon.komoot.io/) |
| 地点検索（住所） | [Nominatim](https://nominatim.org/) |
| 地点検索の最終手段（name タグの直接検索） | [Overpass API](https://overpass-api.de/) |
| 駐車場データ（`amenity=parking`） | [Overpass API](https://overpass-api.de/) |
| 地図タイル | OpenStreetMap |

いずれも OpenStreetMap 由来で、APIキー・課金設定が要りません。検索はボタンを押したときだけ実行するため、
キー入力ごとにリクエストを投げることはありません。Overpass は本家が混んでいるときのためにミラーへ
フォールバックします。

**Google Places API に差し替えたい場合** は `src/api/overpass.ts` の `fetchNearbyParking`
（と `src/api/nominatim.ts` の `searchPlaces`）を同じシグネチャで置き換えれば、UI もスコアリングもそのまま使えます。
Places なら営業中判定や口コミ評価も取れるので、`ParkingLot` に項目を足して `score.ts` の軸を増やす形になります。

## 制約

- 駐車場データは OpenStreetMap の登録内容に依存します。地方や新設の駐車場では登録が薄いことがあります。
- **リアルタイムの満空情報には対応していません。** スコアの「収容台数」はあくまで満車リスクの代理指標で、
  「今その駐車場が空いているか」は分かりません。満空情報を配信しているのはナビタイム、ナビット、
  P-Collection、PPPark! などですが、いずれも法人向けの有償 API です。無料で全国をカバーする
  データ源は存在しないため、必要であればそれらとの契約が前提になります。
- 代わりに **営業時間による「今開いているか」の判定**には対応しています（`opening_hours` タグがある場合のみ）。
- 料金は OSM に登録された文字列に基づく概算です。実際の料金体系（平日/休日、夜間料金、提携割引など）
  とは異なる場合があるため、目安として扱ってください。
- 距離は直線距離に 1.3 倍の迂回係数をかけた概算です（分速 80m で徒歩時間に換算）。実際の道路距離ではありません。
